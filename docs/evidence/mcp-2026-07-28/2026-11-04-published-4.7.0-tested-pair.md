## Dynamic publication race and canary semantics

The published-PyPI canary must continue to test the **latest** artifact:
attestations, source tag, schemas, vocabulary and actual Studio protocol
behavior are strict (a new incompatible peer fails). The compatibility
checker verifies the exact **last independently accepted testedAgainst**
version from the committed matrix, rather than falsely equating it with
every newly published version. The latest also must remain within the
declared supported range and must not be older than testedAgainst.

This separates fast-moving upstream publishing from a truthful pinned
consumer acceptance record without suppressing actual compatibility failures
or widening the advertised support range. Exact-head CI must pass before
the updated metadata is merged.

# MCP 2026-07-28 Post-Release Review

Date: 2026-09-04

Status: **Blocked — production activation is not authorized.**

## Verified upstream progress

- The final MCP `2026-07-28` specification is published at <https://modelcontextprotocol.io/specification/2026-07-28>.
- The official release post dated 2026-07-28 states that the specification is released with a stateless protocol core and updated Tier 1 SDKs: <https://blog.modelcontextprotocol.io/posts/2026-07-28/>.
- PyPI published stable MCP Python SDK `2.0.0` on 2026-07-28; its package documentation identifies v2 as the stable line supporting the `2026-07-28` revision: <https://pypi.org/project/mcp/2.0.0/>.
- Newer stable Python SDK releases exist, but this review does not treat upstream SDK availability as evidence that KiCad MCP Pro has adopted the final protocol.

## Published KiCad MCP Pro state

- PyPI published stable `kicad-mcp-pro` `3.33.3` on 2026-08-27: <https://pypi.org/project/kicad-mcp-pro/3.33.3/>.
- Current public KiCad MCP Pro documentation still instructs Streamable HTTP clients to use `MCP-Protocol-Version: 2025-11-25` after initialization and describes session-era compatibility behavior: <https://oaslananka.github.io/kicad-mcp-pro/>.
- Therefore this review does not record `3.33.3` as a final `2026-07-28` GA server artifact.
- npm currently publishes `@oaslananka/kicad-protocol-schemas` `1.4.1`, but its public package description does not itself establish a final MCP `2026-07-28` activation claim: <https://www.npmjs.com/package/@oaslananka/kicad-protocol-schemas>.
- KiCad Studio still consumes reviewed schema package `1.1.1`; no schema bump is performed by this review.

## KiCad Studio production state

- `mcp.protocolVersion` remains `2025-11-25`.
- `mcp.nextProtocolVersion` remains `2026-07-28`.
- `mcp.activation.state` remains `blocked`.
- `SUPPORTED_MCP_PROTOCOL_VERSIONS` remains `['2025-11-25']` in the production adapter registry.
- The final specification is now recorded in `compatibility.yaml`, but `pythonSdk`, `protocolSchemas`, `serverArtifact`, `extensionAdapter`, and `realPair` activation evidence remain unset.
- ADR 0008 remains `Proposed`.

## Remaining activation blockers

1. KiCad MCP Pro has not been verified here as consuming a stable MCP Python SDK 2.x release for its GA final-protocol path.
2. A published protocol-schema version explicitly reviewed for the final `2026-07-28` contract has not been consumed by KiCad Studio.
3. A stable KiCad MCP Pro artifact advertising `2026-07-28` as its GA protocol has not been verified.
4. KiCad Studio does not contain a production-selectable final `2026-07-28` adapter.
5. Published-artifact real-pair evidence against the final GA protocol is not recorded in this repository.
6. ADR 0008 must remain `Proposed` until the coordinated activation evidence is complete.

## Decision

The release-date freshness trigger has fired, so the repository now records the final specification instead of retaining the 2026-07-27 RC assumption. Production protocol selection remains unchanged because the downstream server/schema/adapter/real-pair gates are still incomplete.

This is a dated evidence snapshot, not a production compatibility claim. Replace or extend it only with stable published-artifact evidence.
